# 6C 受控加密凭证底座

日期：2026-10-04（上海）。状态：默认关闭的独立密文存储、范围绑定、轮换/撤销及临时消费已实现；仅使用自有随机测试材料和临时 SQLite。本模块不是生产密钥保险库或实际任务授权，不打开真实发送。

## 数据与密钥边界

`EncryptedImageCredentials()` 无配置即拒绝。启用必须由可信服务端显式提供 `credentialAccessEnabled=true`、租户、独立 `SqliteImageCredentialStore`、同步授权政策、指定写入根钥匙编号/版本和 `ImageRootKeyPort`。没有环境变量、文件、系统保险库或现有私人钥匙读取器，不生成生产根钥匙，没有 HTTP 或日常开发桥接接线。

独立存储只接受显式绝对路径或内存库；不创建父目录、不默认定位用户状态。应用编号 `ICRD`、schema v1；已有其他应用/版本/表的数据库拒绝且不改原表。WAL/FULL，版本事件与当前头在同一 `BEGIN IMMEDIATE` 事务内提交；不改变原任务 SQLite v5、目录、预算、画布或项目包。

密文采用 AES-256-GCM，32 字节根钥匙、每个事件新生成的 12 字节随机 nonce、完整 16 字节认证标签。AAD 绑定 schema/算法、租户/项目/连接/引用、凭证版本、状态、根钥匙编号/版本、连接修订、操作人、时间及前事件摘要。读取严格校验字段、规范 Base64、标签长度和范围；`decipher.final()` 成功之前不会将解密前缀交给使用者。篡改后即使重新计算公开 SHA，也不能绕过 GCM 认证。[Node crypto 官方文档](https://nodejs.org/download/release/v24.21.0/docs/api/crypto.html)

nonce 同库同根编号/版本的碰撞检查也在写事务内，碰撞拒绝、不重新抽取或自动重试。根钥匙跨库共享、备份恢复或编号更换但实际钥匙未换，仍需要生产钥匙管理规则，不能把此局部检查当全球唯一性证明。根端口须确保编号/版本真实对应指定钥匙，不能只回显请求元数据。

根钥匙以有范围回调借用：请求含完整操作范围、原期望版本及指定根版本；每次根端口调用只能回调一次。缺失/重复/晚回、范围错配、非 Buffer 或非 32 字节拒绝。不沿用 6A 的 `contract-fixture` 凭证端口，不把假端口重标为生产。创建一次根端口调用；轮换和初次撤销分别验证旧事件、加密新事件，各调用一次；重复已撤销历史只验证原终止事件。缺旧钥匙不能静默选新钥匙或覆写历史。

## 版本与撤销

- 引用范围是租户/项目/连接/凭证引用的规范摘要；连接修订包含在认证元数据中。消费要求期望版本和当前连接修订一致，不自动采用“最新版本”。
- 创建期望版本必须为 0；轮换/撤销要求明确现版本。事务内再次匹配现头摘要，跨 SQLite 连接并发只有一次提交，原事件不覆写。事件本身保留操作者、时间、版本链和认证撤销证据，不另写明文审计。
- 撤销追加零长度明文的认证终止事件；重复撤销仅恢复同一已认证事件。终止引用不能复活，后续配置须另用新引用，不删除原历史腾空间。
- 默认每引用最多 31 个活事件，另保留第 32 个终止事件；最多 256 个引用。逻辑密文事件配额 8 MiB、单份 16 KiB；每活引用预留一份完整终止事件及摘要容量，因此正常容量/版本用尽不会阻止撤销。配额可调低但不可升高。这不是整个 SQLite/WAL/磁盘字节限制；存储损坏、无钥匙、无权限或磁盘故障仍可能阻止持久化，须通过服务端停用连接/执行政策先阻止消费。
- 单次读取最多 33 条、单条只取有界文本后再验证字节数；头、事件、顺序、前摘要及时间不一致拒绝，不把孤立历史当作未配置。根钥匙轮换显式指定新编号/版本，旧密文仍保留，并不自动重加密或销毁历史。

AES 认证不提供对完整数据库/备份整体回滚或完整删除的外部反回滚保护。没有独立不可回退计数器、操作系统 ACL、保险库备份策略或运维审计验收；不宣称管理员拿到整个库后无法恢复旧快照。

## 临时消费与授权

服务在接触密文前、根钥匙读取前/后、最终事务提交前、消费前及 `assertCurrent()` 时复查可信同步政策，必须严格 `true`；Promise、异常及非 true 失败关闭。公开方法只返回非秘密元数据或 void，消费回调的返回值不会透传。秘密限 1–4096 字节非空可打印 ASCII（无空格/控制字符）；根钥匙与秘密用自有 Buffer 副本，借出 Buffer 在完成、失败或取消后清零，不修改调用者持有的钥匙/输入。

消费范围含 actor、连接修订、请求/负载 SHA，但这不等于工作负载授权。后续可信政策必须依据实际服务端生产确认、任务、有效运行租约、权威输入/约束、连接/报价、预算事务及当前权限核验，不能接收调用者自报 `confirmed`，不能借用 `local-fixture` 确认或旧 mock 已知费用结算。

消费借出原版本及 `assertCurrent()`；回调应在实际发送前立即调用它，复查当前权限和同库现头。轮换/撤销会使旧 guard 失败，回调结束后 guard 永久关闭。服务不发送请求，也不阻止可信回调故意忽略 guard；已经发送的请求不可被事后撤权“撤回”，回调异常不是未收费证明，不能释放 unknown 预留。

默认超时 5 秒、最多 30 秒、同进程两个操作槽；根端口或使用者 promise 未结束，即使调用方已超时也保留槽位。晚回不能落库或恢复借用，无自动重试。临时清零是尽力措施：不能保证 JavaScript/Node/OpenSSL 内部字符串、调用者副本可靠擦除，也不是恶意可信端口/用户脚本隔离沙箱或跨进程全局资源闸门。错误仅固定白名单码，不透传私人 message/code/cause/路径。

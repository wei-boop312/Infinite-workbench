# 阶段 4 里程碑 4：Google 原生图片协议

日期：2026-10-03。范围：**明确版本的纯协议准备/解析、严格能力映射与本地假响应**。没有配置用户模型、价格、密钥或真实网络执行，不能视为 Google 图片服务接通。

## 官方资料与版本选择

实际打开并核对了 [Google 原生图片指南（GenerateContent）](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)、[GenerateContent 字段参考](https://ai.google.dev/api/generate-content)和[图片输入指南](https://ai.google.dev/gemini-api/docs/image-understanding)。原生编辑是文本与图片输入，返回使用候选内容分段；图片数并非总按指令确定，思考分段也可能包含图片。因此不能直接复用 OpenAI 请求、把第一张图片当最终图，或把提示词当硬像素锁。指南未为本次适配确认可用蒙版字段。[原生图片指南](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)

当前资料同时存在 Interactions、GenerateContent 以及不同图片配置写法；指南页面标题标为 Legacy，部分示例使用比例/尺寸字符串，而字段参考给出枚举。本适配器明确固定 `v1` 的 `generate-content-response-format-v1`，采用字段参考的 `responseFormat.image` 和枚举形式；不猜测服务端兼容、自动切协议或使用 SDK 隐式重试。该字段参考目前只列 `IMAGE_JPEG`，因此此版本仅请求 JPEG / INLINE。真实服务是否接受这一合同仍须另行验收。[字段参考](https://ai.google.dev/api/generate-content#ImageResponseFormat)

## 配置、参数与人工确认

- `GoogleImageProfileSchema` 只用于 `google` 连接，冻结版本、显式模型及逐项尺寸映射。没有默认付费模型、价格表、用户权限推断或自动取模型列表；夹具模型名是不可用于真实调用的占位名。
- 地址限定为 Google AI 的官方 origin，路径按已声明模型构造；拒绝 Vertex、其他中转地址、非标准端口和 API root 猜测。其他供应商仍需自己的明确适配器。这不是已验收的 HTTPS/DNS/SSRF 传输层。
- 只接受显式声明的像素预设，再转换对应比例/分辨率枚举；不将任意 16:9 尺寸换成近似预设。`auto` 不额外暗选分辨率；实际输出尺寸仍待权威资产层核验。映射声明不等于模型实测证据。
- 质量仅 `auto`，背景仅 `auto`；本版本不支持透明度/不透明度控制、PNG/WebP 输出、有损压缩、输入保真度开关、任意额外参数或自定义尺寸。错误能力声明也不能让这些字段被默默丢弃。
- 每模型须自己声明输入数上限，本适配器再加 14 张的本地上限，**不表示任意 Google 模型支持 14 张**；蒙版与 `pixel-exact` 均明确拒绝，不改写为普通参考图或提示词。
- 完整配置、模型、映射、参数与报价进入确认摘要；变更必须重新确认。公开视图不包含地址、凭证引用或原生配置。

## 字节与原生结果

准备模块复用权威输入核验和完整解码/EXIF/sRGB/PNG 归一化，把实际发送图片放入 `inlineData`，保留原始/发送摘要和转换版本。不读取客户端提供的“可信证明”，不发送文件路径、原名或缩略图替代原文件。

本地策略将完整内联 JSON 限制为 20,000,000 字节，累计文本、Base64 和开销后才编码下一张；这是保守工作台上限，不宣称为所有 Google 服务当前配额。响应仍限制为 32 MiB、单候选图片 20 MiB，没有文件上传、远端 URI 下载、工具搜索、视频、多轮历史或思考签名重放。

`parseGoogleImageResponse` 直接解析 `candidates/content/parts`，不制造假的 OpenAI `data[]`。必须单候选、完成状态、恰好一张非思考图片；多张/仅思考/仅文本均拒绝，不由程序选“最佳抽卡”。已知安全阻断、异常分段、URI、混合联合字段、格式漂移、非法 UTF-8/Base64 和错误魔数均拒绝。思考图、生成文本、原始错误与签名不进入结果/审计。

用量按原生实报字段映射输入、输出、思考、缓存、工具和总 token；缺字段保持缺失，不假造零、套用 OpenAI 的总量等式或转换成费用。有足够已知字段才检查总量守恒；异常用量拒绝。无论成功候选、阻断、429、断线或超时，扣费状态始终未知，不自动释放预算/重试。[原生用量定义](https://ai.google.dev/api/generate-content#UsageMetadata)

返回图片仍仅为 **pending-validation 候选字节**；魔数通过不是完整图片验收。本轮特意保留仅 JPEG 头的坏文件夹具，证明协议层不会伪装成已存资产；下个里程碑必须拒绝它并完成全量解码、尺寸、锁区与持久化检查。

## 验证与边界

新增 20 项本地协议/整合测试：严格配置、模型/地址边界、尺寸转换、权威多图引用、参数拒绝、请求上限、确认漂移、思考/多图/阻断、原生用量、坏响应、固定假鉴权的回环 HTTP、并发重放、超时及断线无重试。

测试传输现在可显式注入原生解析器，仍只是测试专用内存幂等，不是持久化生产 Worker。共用候选字节检查抽取到 `imageProtocolResponse.ts`，官方与兼容原有回归全部保留。

首次新增测试有 1 项断言失败：透明 JPEG 被通用 schema 更早拒绝，测试错误地期待供应商能力错误。修正为分别检查格式拒绝/不支持背景，并补安全阻断测试后，最终 `pnpm check`：**187 项单元/集成（24 文件）、6 个工作区构建、29 项真实 Chrome 回归全部通过**。浏览器回归仍检查当前关闭闸门和原有工作台，不意味着原生模型选择界面已实现。

真实执行固定关闭，未读取密钥、选用户付费模型或调用供应商，所有回环测试只使用独立夹具与固定假头。现有 5173 和用户模拟数据未改动。凭证管理、生产网络、有界接收、完整输出验证、商品锁区、真实资产回流、费用结算、事务任务整合与真实服务验收仍未完成。

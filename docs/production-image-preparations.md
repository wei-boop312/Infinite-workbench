# 6D1 独立生产准备与价格依据合同

2026-10-04（上海）。本地合同与自有假价格端口验收；**不是已核验供应商价格、生产授权或真实接通**。实现入口 `productionImagePreparations.ts`，旧 `LocalImageProviders` 的准备、确认、任务与费用语义不变。

## 准备不等于确认或执行

- `ProductionImagePreparations` 无配置即关闭。可信服务端显式配置租户、同一 `SqliteRunKernelStateStore`、准备开关、三类同步权限和 `server-pricing` 端口。没有 HTTP、工作台、实时询价、凭证、DNS/网络、任务创建或预算预留入口；日常桥接未接线。
- 记录固定 `unconfirmed / executionAuthorized=false / realExecutionEnabled=false / protocolPreparation=not-run`。`production` 只表示独立合同的命名空间，不表示生产启用或工作负载许可。
- `requestDraft` 没有 quote、实际任务编号、执行幂等键或已准备/发送负载。独立冻结人工选择、供应商修订/完整能力、原约束、权威原图/蒙版 SHA/尺寸/字节/顺序以及参数。
- 不沿用 local-fixture 确认、动作/执行编号或 mock 的已知费用成功结算。旧确认 schema 与准备读取端口拒绝新记录。相同人工动作字符串在两个命名空间中仍是两个独立动作，不会借用预算或任务。
- `ImageProductionPreparationHarness` 只能显式 contract-fixture 端口，证据必须 `contract-fixture / realExecutionEnabled=false`；独立 `production-contract-fixture` 命名空间。生产类拒绝该端口及其证据，单改 mode/kind 不能通过。假 oracle、源版本或验证成功不能充当真实供应商单价；可信服务端主动伪造新证据不属于此模块的沙箱保证。

## 估价、上限与可信来源

| 来源 | 必填金额 | 依据种类 | 含义 |
| --- | --- | --- | --- |
| server-price-table | estimatedCostMinor、maxCostMinor | server-verified-price | 由已配置服务端价格来源/核验端口给出依据的估价，仍不是实际扣费 |
| manual-budget | maxCostMinor；禁止 estimatedCostMinor | server-approved-budget | 人工预算上限，没有可核验估价，不得补 0 或用上限冒充单价 |

金额为非负安全整数，估价不得超过上限；币种与项目预算精确一致，不自动换汇、添加价格或选模型。准备可以冻结高于当前项目可用预算的人工上限，但不改变预算；后续确认必须由统一预算事务拒绝不可承受的预留。

报价包含 id、版本、来源、有效期；依据包含来源修订、受控不带 URL/查询参数的引用、核验人/时间。绑定精确租户、项目、操作者、连接/修订、模型/能力、操作及完整 basis/选择摘要。basis 包含私有连接、完整权威输入与人工约束、参数和动作，不能挪给另一操作、模型或新选择。

**source 字段和 schema 验证本身不证明可信。** 只能由显式服务器价格端口读取，且独立 verify 回调严格同步 true；客户端选择里不能自报报价/确认/授权。端口必须由未来配置的可信价格表/来源核验实现，当前没有真实供应商 oracle 或价格导入器。实际来源真实性、账单与真实单价仍待单独验收。

read/verify 只接深拷贝；异步/非 true 权限或 verify、错绑定、旧/未来核验时间、已过期价格、不同币种均关闭。报价端口抛出的私密异常不透传。同步可信端口不是不可信代码沙箱，阻塞或恶意回调不能靠 JS 类型强制隔离。

## 当前权威检查与恢复

读取私有准备/目录前先核对租户、provider:read 和 run:create/read；编辑在读取原图收据前要求 asset:read，历史编辑返回前也复查。权限必须同步严格 true，Promise 拒绝，不将 truthy 值当许可。

准备前及价格回调后、保存后复查当前目录修订/能力、权威原图元数据/收据、原约束、权限、显式输出与时间。保存后复查报价有效期与预算币种；写后故障、撤权、过期或漂移同事务回滚记录及存在标记。元数据基础在进入价格端口前限 512 KiB，完整记录另复查。

复用现有纯供应商能力与权威资产政策，但不复用本地执行授权。6D2A 已将静态 validation-only 有效性标记改为独立生产合同，连内存中也不补 estimatedCostMinor=0；不持久化或返回该标记，不用于预算。输出必须显式，auto 拒绝；20 MiB 产物、单边 8192、1600 万像素与后续发送/入库政策不变，4096×4096 报价前拒绝。pixel-exact 与 product.pixels 仍拒绝，不松开旧商品锁；6D1 不提供锁区验收。

相同动作/选择仅恢复一个不可变准备；选择漂移须新动作。恢复允许历史过期或原目录后来停用，不重新询价、改约束、确认、创建任务或预留；当前读权限仍要求。核对历史连接、选择/basis/整体 SHA、原约束 SHA 及 schema 关系。摘要证明内部一致性，不是对抗能重写整个受信数据库的签名或外部反回滚。

## 本机 SQLite v6 与容量

v5→v6 只追加 `production_image_preparations` / `production_image_preparation_presence`，按租户/项目/mode/id 与动作唯一约束；不改旧记录、任务聚合、配置指纹、原图、目录、费用或独立 ICRD/v1 凭证数据库。v6 缺任一新表拒绝打开，不静默重新创建；未来 v7 拒绝，原 v0–v5 增量升级保留。

记录和存在标记必须同一事务追加；不覆盖旧准备。两份存在关系不一致、记录丢失/超长/正文 SHA 损坏失败关闭，不能改为新动作重建历史。每项目新准备合计最多 1000，单份 512 KiB；生产准备计入既有供应商修订/本地准备/响应摘要/生成谱系/任务私有证据共享 16 MiB，不能删除历史腾空间。这不是整个 SQLite/WAL 文件或磁盘硬上限，也不是生产归一化数据库/多进程资源沙箱。完整数据库回滚/删除仍无外部反回滚保证。

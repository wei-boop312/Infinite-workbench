# 阶段 4 里程碑 5A：候选图片权威验证与事务保存

日期：2026-10-04（上海）。状态：**里程碑 5 的资产入库底座通过本地验收，里程碑 5 整体尚未完成**。没有真实供应商调用、生产 Worker、画布供应商选择或任务执行衔接。

## 已实现的调用边界

`apps/api/src/generatedImages.ts` 的 `LocalGeneratedImages` 是可信服务端内部服务，不开放客户端结果登记、收据上传或公共下载入口。调用者必须提供已准备的负载、确认摘要、确认时间、输入转换记录及纯协议解析产生的候选字节；原始连接地址、凭证引用与发送体不会写入生成谱系。

构造时必须注入同步 `authorizeCommit` 端口。该端口在解码前、提交前均在数据库事务内核对请求、确认/发送摘要、确认时间和输入转换记录。缺失或拒绝授权会失败关闭；**当前仅有测试夹具实现此端口，尚未绑定真实任务、租约、执行状态或预算确认**，不能将“必填端口”描述成已经完成的任务集成。

调用路径同时重新核对租户、项目写入/输入读取权限、服务端不可变约束、蒙版引用、原图二进制摘要与权威收据。浏览器传来的尺寸、SHA-256、收据或任务编号不构成执行证据。原有真实执行闸门保持关闭。

## 完整解码与容量边界

- 从候选复制独立字节，跨异步解码不再持有调用者可修改的 Buffer；MIME、魔数、SHA-256 与请求输出格式必须一致。
- 共用 `staticImageDecoder.ts`，完整读取经 EXIF 定向、sRGB、RGBA 规范化的像素，验证宽高与像素字节数；元数据读取不是完整解码。拒绝截断/伪格式文件、APNG、多帧 WebP/GIF/AVIF及超界图片。
- 候选输出限静态 PNG/JPEG/WebP、20 MiB、1600 万像素、单边 8192。原图与输出完整核验共享同进程并发上限 2，像素解码阶段使用 5 秒超时。后续 5B2A 已让输入协议归一化共用这两个槽；其他进程不在计数内，不能据此宣称生产全局资源隔离。
- 原图和生成图共用每项目默认 512 MiB 二进制镜像上限，资产目录上限 10000；非法、非整数或超出本机上限的容量配置拒绝。
- 完整解码后的真实尺寸必须同时满足冻结约束和显式请求，不自动裁剪、缩放或换格式。请求透明背景必须存在真实透明像素；不透明背景不允许透明像素。
- **保存原始供应商字节，不重新编码产物**；EXIF 定向用于尺寸/像素校验。此步骤不是锁区保护合成，记录固定 `protectionApplied=none`。请求 `pixel-exact` 或约束含 `product.pixels` 时明确拒绝，不凭提示词、蒙版或模型能力声明承诺硬像素保真。

4096×4096 超过本机 1600 万像素上限。某协议能表达该尺寸，不代表本机允许接收；后续报价、确认和发送前必须复用同一限制，不能先调用再下采样或静默改模型。

实现使用锁定版本 sharp；设计核对其[构造/像素限制](https://sharp.pixelplumbing.com/api-constructor/)、[元数据语义](https://sharp.pixelplumbing.com/api-input/)及[完整输出/超时](https://sharp.pixelplumbing.com/api-output/)文档。当前只是在本机进程做有界验证，不是生产恶意文件隔离沙箱。

## 原子保存、谱系与重放

SQLite 模式升级至 v3，v1/v2 旧任务、预算、账本、目录和原图数据保持不变；未知更高模式拒绝覆盖。新增生成记录及存在标记，没有清空、替换或重新结算旧状态。

一次事务提交原始 BLOB、服务端图片收据、生成记录、存在标记及资产目录。任何一步失败全部回滚，不留下目录占位或孤立的“成功图片”。生成资产使用服务端随机编号、完整 SHA-256、实际尺寸和受控存储键；画布仍只引用 `assetId`，没有把供应商 Base64 塞进画布。

不可变生成记录保留完整请求参数与报价、确认时间/摘要、实际发送摘要、协议、约束快照、输入原始/转换后摘要和转换版本、主参考图以及原始协议返回/用量快照。多参考图和蒙版的完整关联保留在请求与转换记录中；资产上的 `sourceAssetId` 只是主参考图，不替代完整谱系。

同租户/项目/任务的完全一致重放返回原资产，包括另一数据库连接或重启后的重放。更换字节、发送摘要、确认时间、返回/用量快照或转换记录会冲突，不能覆盖版本。正文、收据、谱系、目录或单独存在标记损坏/缺失时失败关闭，不假装“没有结果”而重新生成。这不是抵抗具有本机数据库管理权限者同时篡改全部表的安全边界。

内部只读查询也受租户及项目读取权限控制，并重新核对正文摘要与目录。当前没有新增公共二进制下载路由、工作台生成预览或浏览器资产缓存回流。

## 产物与费用不混淆

纯协议返回仍为 `pending-validation`，其原始快照不被改写；新生成记录单独标记资产 `validation=verified`。本入口只接受扣费 `unknown` 的原始解析快照，不允许调用者提交“免费”收据。

生成记录不是费用结算或任务终态：此服务**不写任务、预算或账本**。好图、坏图、保存失败均不能释放未知扣费预留；历史返回快照也不能被之后的核账覆盖。后续必须使用现有追加核账与任务事务层单独处理费用、任务状态和人工重试。

确认有效性按原始确认时间核对；已授权调用的响应晚于报价有效期，不应为了保存结果重新付费。该时间必须由下一步服务端执行快照证明，当前不是客户端授权机制。现有测试专用内存传输也不是生产队列。

## 本地验收证据

新增 23 项单元/集成测试，覆盖 PNG/JPEG/WebP 真实解码、EXIF、实际透明性、魔数伪装、原生 Google 解析后仅含 JPEG 魔数的假产物、动画/尺寸/容量/并发限制、字节所有权、权限/执行授权撤销、发送与谱系漂移、跨连接重放、提交失败回滚、数据库损坏及 v2 升级保留旧图片和账本。独立 mock 任务测试证明本服务不会变动未知费用预留，但**不代表该 mock 任务已经与生成服务一体化**。

最终 `pnpm check` 通过：25 个测试文件、210 项单元/集成、6 个工作区构建、29 项 Chrome 回归。Chrome 项是已有画布/任务/安全闸门回归，本次没有新增生成结果 UI，不能把它们说成新 UI 的验收。

所有测试使用自有临时目录或独立 4173 工作台状态，不写用户日常状态目录；没有读取供应商密钥、发起付费请求或远程推送。

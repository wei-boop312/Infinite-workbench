# 本机权威图片内容校验

日期：2026-10-03。阶段 3 第九里程碑；仍为单人本机开发、零费用模拟。

“已登记资产”不等于“已验证图片”。浏览器的 MIME、大小、尺寸、编号、路径和指纹都是待核对声明，不能凭它们占用预算或启动任务。新服务仅使用自己接收、完整解码、保存并重新核对的原文件。

## 数据流与权限

1. 打开任务面板只通过 `/studio-api/context` 登记不可变资产和约束元数据，不自动上传图片。
2. 用户点击预估、确认、执行排队任务或人工重试时，客户端从 IndexedDB 读取所需原文件，计算完整 SHA-256，先送原图再送蒙版。
3. `POST /v1/projects/:project/assets/:asset/verification` 接收原始二进制，要求可信身份和 `asset:write` 权限；项目和租户从服务端身份/目录查找，不允许客户端指定租户。
4. 校验 Content-Type、字节数、实际摘要、已有资产指纹和文件魔数，用 sharp 0.35.5 完整解码全部静态像素，再核对尺寸；EXIF 方向按自动校正后的尺寸计算。
5. 解码不占任务数据库写锁。最终在短 SQLite 事务中重新核对目录和权限、项目配额、资产不可变版本及蒙版底图，原子保存原文件 BLOB 与 `VerifiedImage` 服务端收据。
6. 创建、确认、领取租约、凭租约启动和人工重试时，在任务事务内查收据并重新散列数据库原文件；失败不新增任务、预留或供应商请求。已有预留不因图片丢失而自动释放，未开始的任务仍可人工取消。

浏览器只请求同源本机接口，不上传外网，不接触供应商凭证。正式 API 默认不注入图片服务，返回 `asset_verification_not_configured`；本地 Vite 入口仍要求回环 Host、同源以及 `x-canvas-local`。只读身份可以查看验证记录，但不能写入。

## 收据与存储

- 数据库 schema 从 v1 原子升级为 v2；旧目录、财务账本和 JSON 迁移备份保持不变，旧资产不会自动成为“已验证”。
- `verified_images` 以 `(tenant_id, project_id, asset_id)` 为主键，独立存储原始字节和收据；媒体不进入画布文档或任务聚合 JSON。
- 收据包含真实格式、方向校正后的尺寸、大小、完整内容摘要、登记元数据摘要、服务端生成的本地存储定位符、核验人/时间与解码器版本。
- 同编号只能重放相同内容和登记记录，不能覆盖。响应丢失或另一个本机服务同时上传时，返回同一收据，不重复占用项目空间。
- 返回收据不是客户端可提交的证明；不存在“提交 verified=true”或上传收据即可通过的接口。
- 每次读取检查收据摘要、项目/租户/资产归属、正文大小与 SHA-256。损坏正文/收据返回不可用，缺少验证记录则阻止执行，不从浏览器声明或旧文件静默补回。
- 当前没有原文件下载/跨设备恢复入口；浏览器原图丢失后界面要求从既有备份恢复，不能只用缩略图或服务端历史收据继续确认。

## 蒙版与资源限制

- 蒙版必须为有 alpha 通道的 PNG，属于当前项目、绑定已验证非蒙版原图，真实尺寸完全一致；收据绑定底图实际 SHA-256，不能换底图复用。
- 静态 PNG/JPEG/WebP/GIF/AVIF 可核验；多帧、APNG 控制块和 AVIF 序列拒绝，不把首帧冒充完整输入。SVG、PDF、视频等不进入此图片任务解码器。
- 原文件上限 30 MiB，像素上限 1600 万，单边不超过 8192，完整解码超时 5 秒；每进程最多同时核验 2 个文件。
- 每租户/项目的本机镜像累计上限 512 MiB；重复编号重放不重复计算。当前无引用感知清理入口，达到配额时明确拒绝，不能手动删数据库行绕过历史引用保护。

## 验证与仍然存在的边界

专用临时目录测试覆盖匿名/只读/跨租户、伪造声明、截断像素、静态格式和 EXIF、动画、大小/像素/边长/配额、蒙版来源、并发重放、重启、故障回滚、损坏收据/正文、旧记录升级，以及输入丢失后预算和执行闸门。真实 Chrome 覆盖本机上传响应丢失、原文件丢失和绘制蒙版后完整确认执行；测试不写用户状态目录。

这只是本机权威**内容**校验，不是生产权威资产授权平台。生产仍需真实成员权限、PostgreSQL/对象存储事务适配、隔离解码与恶意文件扫描、引用感知删除、总容量/跨进程资源限制、一致备份与跨设备恢复。原始字节保留而非重新编码；未来供应商适配器必须明确 EXIF/颜色/蒙版坐标语义，不能悄悄变换商品像素。

# 阶段 4 里程碑 5B1：供应商目录与未确认准备单

日期：2026-10-04（上海）。本文主体记录 **5B1 未确认准备单的历史验收**；后续本地确认/租约/假传输/实际产物授权、回读与缓存已独立验收，供应商选择/准备 UI 的 5B4A 见 `docs/image-preparation-ui.md`。没有选择用户付费模型、读取密钥、解析凭证或发供应商请求。

## 已实现

`LocalImageProviders` 将严格图片连接合同持久化到本机 SQLite，按租户/项目隔离。连接采用连续修订和追加历史：首次为 1，修改必须匹配旧版本，停用也是新版本。相同修改重放不重复写入，不同连接中的过时写入不能覆盖较新版本。读取时同时核对当前版本、完整连续历史、归属与摘要；单独记录或头标记损坏/缺失会失败关闭。

配置写入仅有可信服务端内部 `registerRevision` 方法，要求独立 `provider:manage` 权限；没有 HTTP 配置写入/删除接口。公开读取需要 `provider:read`，隐藏 Base URL 与凭证引用，继续区分声明能力、诊断及实际请求证据；目录存在不代表连接可执行。初始目录为空，不自动添加供应商、模型、价格或诊断结果。

新准备接口只接收明确的连接修订、模型/能力版本、约束编号、操作、输入/蒙版编号、参数和人工动作编号。报价、收据、原图尺寸/SHA、任务编号、确认时间、地址及密钥不是客户端可写字段。

编辑输入从权威原文件与收据重新计算/核对，约束与蒙版来源由服务端查找。5A 共用的 `imageAssetPolicy.ts` 在估价前和提交前核对输出规格、像素/边长上限、输入和蒙版关联；`pixel-exact` 和约束中的 `product.pixels` 仍拒绝。4096×4096 超过 1600 万像素上限，在估价前拒绝，不先生成后降级。

可信同步估价端口目前仅接收/输出 `mode=local-fixture` 的假报价，冻结证据引用、金额、币种、版本及有效期。币种须匹配服务端项目预算，不做汇率换算。开发桥接的单图预估/上限是模拟 25 分、有效期 5 分钟；不是供应商实际价格，更不是将来请求的付费授权。

## 准备快照不是执行快照

不可变准备记录保留原选择、连接/能力完整版本、原图引用、约束、参数、报价和创建人/时间，分别计算选择摘要和完整冻结摘要。请求模板**没有 `jobId` 或执行幂等键**，固定：

```text
status = unconfirmed
executionAuthorized = false
protocolPreparation = not-run
```

5B1 的创建/读取方法不确认、派发、执行或预留预算，不能实现 5A 的 `authorizeCommit`，也不能给原有 mock 商品精修提供新的确认。5B2A 新增独立确认方法和协议准备/统一任务事务，不改变原准备单；临时用于静态合同验证的占位编号不会持久化成任务，不用于协议发送摘要。

此步骤只验证声明合同和本机资产政策。独立 5B2A 已实现输入归一化、各协议完整构造、负载摘要/转换版本、人工确认及预算冻结；租约绑定和发送证据仍须在 5B2B 完成。原生/兼容连接配置存在不能据此宣称真实请求通过；`custom` 没有适配器，准备入口明确拒绝。

同动作、同选择的重放恢复原准备单，不重新估价。参数漂移冲突；新报价或连接修订需要新动作。历史准备单即使过期或当前连接已变化，也可作为历史读取，但始终是未确认/未授权；后续确认必须重新核对当前连接、输入、约束和报价有效性，不得用历史恢复绕过检查。读准备单需要项目任务读取权限，创建另需任务创建权限及相关输入资产读取权限。

估价期间权限、连接或约束变化会阻止保存，相关数据库修改在同一事务回滚。准备单写入与存在标记共同提交；记录损坏、丢失或摘要漂移时不通过重报价覆盖原动作。

## 本机持久化与接口

数据库 v4 仅新增目录修订/当前版本、准备单/存在标记表，不重写旧原图、生成资产、任务或账本。本机边界为每项目 64 个连接、每连接 32 次修订、1000 份准备单；单记录 512 KiB。目录历史/准备元数据与后续 5B2A 执行快照共同核算默认 16 MiB，不删除历史腾空间；与图片二进制镜像额度分开。

- `GET /v1/projects/:projectId/image-providers`：受权限保护的公开目录。
- `GET /v1/projects/:projectId/image-providers/:connectionId`：当前公开版本。
- `POST /v1/projects/:projectId/image-preparations`：创建/恢复未确认准备单，请求体不超过 128 KiB。
- `GET /v1/projects/:projectId/image-preparations/:id`：历史准备单公开视图。

所有响应 `no-store`。未注入服务时目录入口返回 503；匿名为 401，未知/无权限范围不泄露记录。没有配置写入、执行或产物登记接口；5B2A 的独立确认接口见对应文档。纯静态构建不包含开发桥接。

Vite 桥接只为已登记本机项目提供目录读取和零费用准备/暂存确认服务，仍受回环主机、同源与本地标记保护，不授予配置管理权限。配置确认内核后健康状态为 `catalog-preparations-staged-confirmations`，旧目录服务仍是 `catalog-and-preparations-only`，未注入仍 `contracts-only`；`realExecutorsEnabled=false` 始终不变。工作台尚无供应商选择/准备单界面，目录默认空。

SQLite 和摘要只提供本机一致性/损坏检测，不是生产 PostgreSQL、密钥加密服务、SSRF 防护、多成员鉴权或抵抗本机数据库管理员同时篡改全部记录的安全边界。

## 验收

新增 28 项单元/集成及 1 项 Chrome 回归；覆盖修订竞争、重放、权限与损坏、估价变化/有效期/币种、原图和蒙版、容量与原子回滚，以及 v3 升级实际保留原图、未知费用任务、账本与预留。旧资产入库及画布/预算回归保留。

首次新增 26 项测试中 20 项失败，原因是将结构化错误码当成中文错误消息匹配；改为检查错误的 `code` 后通过，再补两项提交边界测试。最终完整 `pnpm check`：26 个文件、238 项单元/集成、6 个工作区构建、30 项真实 Chrome 全部通过。新增浏览器证据仅证明空目录、伪报价拒绝、不占预算和无外网，不冒充未实现的模型选择/执行 UI 验收。

测试使用自有临时数据库或独立 4173 状态，不写用户日常状态，不读取私人密钥、不推送或部署。

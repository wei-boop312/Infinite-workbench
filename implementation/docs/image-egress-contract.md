## 不可混淆的权限边界

`ImageEgressFixtureHarness` 只能显式配置 `contract-fixture` DNS、凭证及传输端口，凭证与传输的 realExecutionEnabled 必须是 false；无配置拒绝。没有读取环境/文件/私人密钥的实现、fetch/HTTPS/DNS 客户端、HTTP 路由或日常桥接接线。所有 Key 都是测试自有常量；公开供应商、画布、项目包和日志格式不增加秘密字段。

调用实际三种纯协议构造后核验连接/请求范围、修订、能力、报价、请求及实际负载 SHA、方法、Content-Type、原协议端点和鉴权方案。官方按原 API 根拼接既有图片路径；兼容中转严格沿用冻结配置；Google 严格原固定原生路径和 x-goog-api-key。不能把准备请求的指纹当成已发送、任务租约或用户确认。此模块**不查询 SQLite 或实际任务/约束收据，不产生持久化执行证据或资产**；未来接入仍必须通过现有实际任务/租约、完整确认与共享权威资产政策。

配置租户和调用者范围必须一致，可信同步 authorize 对完整凭证范围/连接修订/请求和负载摘要严格返回 true；Promise（含异步拒绝）失败关闭，不等待其结果。DNS 前、DNS 后、凭证消费前复查权限、报价及服务端目标名单。凭证租约须完整匹配租户/项目/调用者/连接修订/引用/请求与负载摘要，不接收调用者已确认布尔值。

原图/输出沿用共享 8192 单边、1600 万像素政策；4096×4096 先拒绝。此出站合同要求明确人工输出尺寸，auto 拒绝，不保证自动尺寸会符合冻结输出；既有纯协议的 auto 声明不因此变成可执行。pixel-exact 继续由原合同拒绝，product.pixels 的权威原约束政策仍须现有任务层核验，不宣称此模块已实现锁区。

## 地址和连接合同

原 Base URL 先于 URL 规范化检查：HTTPS、ASCII 域名、明确路径，不接受 IP 字面量/整数/八进制/十六进制、凭证、查询、片段、百分号、反斜线、点路径或重复路径分隔。域名/端口仅匹配服务端逐项名单，无通配或后缀匹配；允许服务端明确配置的 HTTPS 非默认端口。路径来自原协议/冻结配置，不接客户端任意 URL。端点/鉴权/负载不一致在 DNS 或取凭证前拒绝。

显式 resolveAll 合同必须提供所有 A/AAAA，最多 32 个；空/错误族/一个不允许地址即整体拒绝，不挑选一个好地址掩盖坏项。IPv4 拒绝 IANA 特殊用途全部块（包括少数全球可达协议例外）、多播/保留地址；IPv6 只接受 2000::/3 内非特殊/转换/文档块，拒绝 mapped、NAT64、ULA、link-local、zone 和 dotted 嵌入。该保守策略不等于公网路由保证，可能拒绝特殊用途的可达地址。另拒绝 Azure 平台地址 168.63.129.16；部署可配置最多 1024 个 additionalDeniedAddresses，只增阻断，IPv6 不同写法按数值等价。

取一份固定公共地址，不进行第二次 DNS、轮询失败转移、自动重试或重定向；解析最多有效 30 秒，凭证等待跨过有效期或时钟倒退拒绝。发送端口必须使用此 address/family，保留原 hostname/servername、证书核验 true、redirects=error、retries=0、proxy=disabled。**这些目前是假传输参数合同，不证明未来 HTTPS 客户端真的遵守，不是 TLS/生产 DNS pinning 验收。**未来客户端不得再次自行解析、沿用任意代理/共享连接池或关闭证书核验。

设计参考了 [OWASP SSRF 官方指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) 的目标名单、全 A/AAAA 检查和禁止重定向；阻断前缀按 [IANA IPv4 注册表](https://www.iana.org/assignments/iana-ipv4-special-registry)及 [IPv6 注册表](https://www.iana.org/assignments/iana-ipv6-special-registry)核对。Azure 地址依据 [Microsoft 官方说明](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16)。这些来源均已实际打开，不运行资料中的真实网络探测。正式部署仍需出口网络隔离、平台/路由阻断以及注册表变化审计，应用前缀检查不是完整防火墙。

## 凭证、资源和返回包

凭证只能通过受控消费回调使用一次，1–4096 字节可打印非空 ASCII，拒绝 CR/LF/空白/控制字符。凭证复制 Buffer 在消费结束清零，临时认证头移除；原凭证 Buffer 生命周期由可信端口负责。JavaScript 字符串不可可靠擦除，**不是密钥保险库或用户脚本沙箱**，也无法阻止恶意注入的可信端口留存秘密或自行联网。真实实现需单独验收加密/工作负载身份、密钥版本/轮换/撤销和实际授权，不使用此测试夹具作持久秘密存储。

每份 harness 单次使用（包括失败），一次假发送，无自动重试。请求复制后固定不受异步期间外部原 Buffer 改动影响，最多 64 MiB 且可调低；响应最大 32 MiB 可调低，头最多 100/16 KiB、单分片最多 8 MiB、4096 个非空分片，声明长度和实际完整流须一致。仅 application/json，压缩拒绝，不跟随 Location 或供应商产物 URL。返回只是服务端内部原始协议包，不是合格图片或零计费证据；后续原解析/完整产物校验仍必须执行。

默认总等待 5 秒，最大 30 秒，取消涵盖 DNS/凭证/传输及迭代读取；同时最多 2 份。同进程不合作端口/迭代操作尚未结清时保留槽，调用方超时不能腾空无限后台操作；可信端口需遵守信号，否则可能占满槽，不能宣称任意异步代码可强制终止。退出/失败调用迭代器 return，临时请求及读取分片尽力清零。异常只返回固定错误码，不传播供应商/DNS/凭证原消息或 cause，不修改费用；失败不是已确认未扣费。

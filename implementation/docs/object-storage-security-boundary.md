# 对象存储安全边界

阶段 2 只实现服务端合同和内存假网关，不连接 S3、R2、OSS 或任何外部网络。正式适配器必须保持以下边界。

## 信任边界

- 浏览器不能持有云厂商密钥，也不能自行拼接对象路径。
- API 服务先从服务端会话解析 `tenantId` 和 `actorId`，再检查该身份在目标项目上的 `asset:read` 或 `asset:write` 权限。
- `tenantId` 不接受客户端请求体或查询参数输入；同名项目跨租户仍视为完全不同的安全域。
- 对象键由服务端生成，并同时绑定租户、项目和资产编号。

## 签名凭证

- 上传签名绑定项目、资产、MIME、精确字节数和完整 SHA-256。
- 下载签名只能针对服务端已记录且属于当前租户、项目和资产的对象签发。
- 凭证默认 5 分钟有效，最大不得超过 15 分钟，并且只允许成功使用一次。
- 凭证使用 HMAC 完整性保护；篡改、过期、重复使用和请求方法不匹配都会被拒绝。
- 签名路径是短期能力凭证，不得写入画布文档、资产元数据、日志正文或长期缓存。

## 上传与下载

- 上传必须匹配签名要求的 `Content-Type`、`Content-Length` 和 `X-Content-SHA256`。
- 服务端对实际收到的内容重新计算 SHA-256；只相信请求头是不够的。
- 下载响应使用 `private, no-store`，避免共享缓存保存租户资产。
- 越权读取统一返回“对象不存在”，避免泄露其他租户是否拥有该对象。

## 默认关闭

- `createApiServer()` 默认没有对象存储网关，签名端点返回 `storage_signing_not_configured`。
- 当前 `InMemorySignedObjectGateway` 仅用于自动测试和协议验证；进程退出后数据消失。
- 接入真实存储时，应通过服务端环境密钥或工作负载身份创建新适配器，不能把密钥传给前端。
- 正式适配器还必须补充持久审计、速率限制、恶意文件扫描、服务端加密策略和生命周期清理。

## 当前 API

- `POST /v1/storage/grants`：身份认证、项目权限检查并签发上传或下载凭证。
- `PUT /v1/storage/transfers/:token`：内存假网关的受签名上传入口。
- `GET /v1/storage/transfers/:token`：内存假网关的受签名下载入口。
- `GET /health`：公开报告签名网关是否显式启用；真实执行器状态仍保持关闭。

## 阶段 4 生成资产的本机只读回读

5B3A 另提供 `GET /v1/projects/:projectId/generated-assets/:assetId/content`，见 `generated-asset-readback.md`。它从服务端 SQLite 读取已经完整验证并与实际任务绑定的原始图片，不复用上述内存签名网关、不接外部存储或供应商 URL，不接受客户端租户/文件路径。每次认证和检查项目 asset:read，核验完整任务/原包/谱系/目录/正文证据；返回原字节、MIME、精确长度、SHA 和 private/no-store，不暴露内部生成记录或私有连接。

默认 API 未配置此服务时关闭，日常本地桥接启用只读服务但仍无生成执行政策；本机模拟角色不等于生产会话认证。读取不写任务/预算/账本，不恢复过期租约，不重发、核账或自动释放未知预留。5B3B 已接浏览器受控下载/私有原文件与代理缓存，见 `generated-asset-cache.md`；不把本地缓存当成执行或新的读取凭证。任务结果画布回流仍未开放；Service Worker 继续跳过 /studio-api/ 与 /v1/，不能把授权请求存到共享缓存。

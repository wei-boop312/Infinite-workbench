自动派发不是自动续做开发：开发工作可以自动接续，但工作台中的排队输出仍须用户点击执行。取消也不会把已经完成的结果删除或把已消费金额退回。

## 额外安全门槛

- 每次任务变更在 SQLite 事务内重载并校验金额守恒；多真实进程并发、进程提交前退出、写入故障、坏摘要和锁竞争有回归，不退回旧账本或清空余额。
- 创建/确认/领取/启动/重试依赖保存的真实图片，客户端声明不足以执行。正文和证明原子提交、读取重新散列、蒙版绑定底图摘要和真实尺寸。
- 普通执行、核账和超额审批的权限不同；申请人不能自批，审批不足预算时继续冻结，不扩大项目总额度。
- 本地 Vite 的设计师/审批人只是模拟身份；正式 API 不注入服务时保持关闭。静态发布不包含开发桥接。
- 浏览器仅使用固定同源入口，预算/任务响应不进入离线缓存；本轮没有真实 API、MCP、密钥读取或外部网络调用。

## 本轮验证结果

- `pnpm check` 最终通过：20 个测试文件、117 项单元/集成测试、6 个工作区构建、28 项真实 Chrome 回归。
- 新浏览器专项测试最初在创建响应完成前读取了旧批次编号。改为等待创建响应并核对当前选择值后，单项连续重复 3 次通过，再跑完整检查通过；未将首次失败记为成功。
- 已有 500 节点、鼠标/触控、离线、双标签冲突、项目包、蒙版、资产备份与超额审批均通过。
- 所有财务金额都是假定价，真实费用为零。测试状态使用系统临时目录或 `test-results`，不写用户工作台目录。

## 不属于本次通过的内容

- PostgreSQL 规范化生产事务、真实队列/跨机器 Worker、成员鉴权、云对象存储、在线一致备份和恶意文件隔离尚未完成。
- 假模型已知未扣费的超时可以释放预算；**真实请求超时/响应丢失不能照搬该逻辑**，应先进入未知计费并禁止自动重试。
- 假成功返回的是模拟任务记录，不是真实生成图片；阶段 4 必须验证返回二进制、资产化、真实或明确标记的估算用量。
- 当前生产角色权限、凭证管理和公开部署门槛不因本阶段通过而解除。现有 5173 进程未强制重启；新服务经独立 4173 实例验收。

## 权威租约边界

统一任务内核增加仅服务端内部的 claimImageBatch、inspectImageLease、startImageJob、reconcileImageBatch。必须显式配置同步可信 validateImageTask；缺失则失败关闭。LocalImageTaskLeases 与 SqliteRunKernel 必须共用同一个事务存储实例。

createImageTaskValidator 从本机数据库重新核对原准备单完整摘要、当前连接/能力完整修订、权威原图/收据、约束、尺寸、商品锁及供应商/资产权限。领取和启动另要求 run:execute；准备前要求 run:read。任意漂移要求新动作重新确认，不能放松旧 product.pixels 保护。

领取共用现有最大领取数量、项目/供应商并发槽位及持久化供应商时间窗，包括旧 mock 任务；没有另开一套不受预算/并发限制的队列。跨 SQLite 连接仅领取一次。当前没有新增全局并发、生产隔离或跨进程解码政策。

旧公开创建/确认/领取/执行/派发/检查/重试入口继续拒绝图片任务；新内部方法没有 HTTP 路由，日常本地桥接也未注入执行政策。供应商目录仍默认空，没有读取凭证或启用真实生成。

## 重建与原子意图

服务先在事务内验证租约编号、执行器、实际领取人及当前权威政策，再读取输入字节；不能用拥有相同项目权限的另一人冒用租约。事务外异步重建官方、兼容 JSON/multipart 或 Google 原生负载；不在 SQLite 写锁内 await。

启动事务重新检查当前权威政策、报价和有效租约，并逐项匹配确认中的请求指纹、真实负载 SHA-256/字节数/Content-Type 与输入转换谱系。最终同步政策检查也可能跨过时间边界，所以写意图前再次检查租约到期。

原子保存 ImageDispatchIntent、其完整指纹、running 状态及 job-started 审计。意图绑定实际任务/批次、领取人/执行器/租约、确认执行快照摘要、请求/负载/转换摘要和记录时间。恢复核对对应租约、审计、时间、金额与不可变确认；缺失、孤立、错配或损坏均失败关闭，不把记录缺失当作可重新发送。

**意图固定 mode=local-fixture、transport=not-connected。它不是已发送或已收到供应商响应的证据，更不是 5A authorizeCommit 授权。** 不伪造 providerRequestId，不生成假 outputAssetId。当前 prepareStart 返回记录和 started，不返回地址、凭证引用、负载字节或执行能力令牌。

首次启动返回 started=true；并发重复、重启或历史恢复返回 started=false。重放不重新解码原图，也不因报价过期或连接停用触发第二次启动。需要现有读取/执行权限及原租约身份；不能从历史恢复推导任何新发送授权。

## 失败、预算和容量

- 未启动的租约过期可以重新领取新租约；旧租约不能启动。从未启动的任务可取消，释放确认上限预留。
- 已写意图后的运行超时、租约过期及不共享数据库的内存恢复均保守进入 billing_unknown。没有响应或图不等于费用为零，保留 maxCostMinor 预留，不沿用 mock 已知费用自动结算，不自动重试/取消。
- 仍可在统一账本人工核账并保存证据。明确未扣费才释放；已扣费按实核金额结算。超出预留需要第二人审批，批准不能提升项目预算或导致自动执行。未产生资产时核账后保留 failed 记录；原不可变确认不被核账覆盖。
- 同进程最多两份派发协议准备，不建无限等待队列；输入归一化共用原图/输出的两个解码槽。目录历史、准备单、确认快照及意图共用每项目默认 16 MiB 元数据额度，单份不超过 512 KiB；保存故障回滚意图/运行状态/审计，不删除历史腾空间。
- 输出仍限 20 MiB、1600 万像素、单边 8192；4096×4096 在确认/启动前拒绝，不先付费后缩图。pixel-exact 和 product.pixels 保持拒绝；不是生产全局资源闸门或恶意文件沙箱。

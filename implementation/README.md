# AI 电商视觉无限画布

2026-11-09：本目录已作为商业无限画布隔离迁移分支。新增双层契约、本机数据库/身份/私有图片、项目与画布保存入口，以及固定模板/真实CPU适配验收。运行`pnpm local:dev`访问`http://127.0.0.1:4310`，首次设置本机账号。当前完整状态及复核命令见[实施进度](docs/IMPLEMENTATION_STATUS.md)。下文保留旧版本功能说明，不代表已完成云端产品迁移。

阶段 1 可靠画布内核、阶段 2 资产/约束及存储安全边界、阶段 3 单人本机任务与成本内核的假执行器验收已完成；下一阶段是多供应商图片 API。默认仍只运行假执行器，不连接模型、不读取供应商密钥、不产生费用。阶段 3 验收证据与生产边界见 `docs/phase3-acceptance.md`。

阶段 4 的严格供应商图片合同、默认关闭闸门、官方图片纯协议、兼容中转差异及 Google 原生纯协议/本地假响应已通过本地验收。里程碑 5 的第一步——候选图片完整验证及不可变资产/谱系事务保存——也已通过本地验收，但尚未接到工作台、任务执行租约或真实供应商；边界与证据见 `docs/image-provider-contract.md`、`docs/openai-image-protocol.md`、`docs/compatible-image-protocol.md`、`docs/google-image-protocol.md` 和 `docs/generated-image-ingestion.md`，实施顺序见 `docs/phase4-provider-plan.md`。

里程碑 5B 的供应商目录与未确认准备单也已持久化并通过本地验收：连接修订防覆盖，服务端冻结输入/约束/参数及明确标记的假报价。目录默认空，尚无模型选择界面；准备单不冻结预算、不创建任务、不授权执行。详见 `docs/image-provider-preparations.md`，下一步是实际确认/任务/租约衔接。

## 目录

- `apps/web`：React + React Flow 画布。
- `apps/api`：项目、资产、预算与任务入口骨架。
- `apps/worker`：模型 API 与 MCP 执行器进程骨架。
- `packages/contracts`：跨进程数据合同。
- `packages/canvas-schema`：画布文档版本与迁移器。
- `packages/testing`：假执行器和故障测试夹具。
- `tests/e2e`：真实浏览器的鼠标、触控、500 节点、离线恢复和零外部请求检查。

## 当前能力

- 撤销、重做、内部复制粘贴、删除。
- 图片资产占位节点、可编辑文字节点。
- 多选建立分组、解散分组，父子关系写入 v2 画布文档。
- 图片、文字、约束端口声明数据类型；不兼容、重复和循环连接在落图前被拒绝。
- 自动整理按工作流依赖重排顶层节点，保持分组内子节点相对位置。
- 650ms 防抖自动保存、单调递增修订号与刷新恢复。
- 双标签页乐观并发检查；冲突时可另存当前修改或载入另一标签版本。
- 项目草稿彼此隔离；离线外壳支持断网重载，保存失败可重试或下载恢复文件。
- API 提供带 `If-Match` 条件修订的画布读写合同，为阶段 2 云端持久化预留冲突语义。
- 无版本/v1 画布自动迁移到 v2，未来版本拒绝加载。
- 浏览器使用轻量合同校验入口；服务端保留完整校验，避免把不必要的校验库带进首屏。
- 支持本地图片和视频导入，原文件与轻量预览保存在 IndexedDB，画布只保存 `assetId`。
- 32 MB 以内媒体使用完整 SHA-256 指纹去重；同一项目重复导入会复用资产，避免重复占用存储。
- 资产库按项目隔离，可把同一资产多次放入画布而不复制二进制。
- 约束节点可以冻结商品/品牌锁定项、可编辑区域、可选蒙版资产、品牌规则和输出规格。
- 约束快照不可变；每次调整创建新版本，后续任务只能引用明确的 `constraintSnapshotId`。
- 可在商品底图上使用画笔、矩形、多边形、套索和橡皮绘制透明 PNG 蒙版；蒙版编辑器拥有独立的 8 步撤销/重做，每次保存创建独立蒙版资产版本。
- 资产库显示项目占用和浏览器配额；画布、蒙版来源或历史约束仍在引用的资产禁止删除。
- 支持逐个移除或批量清理未使用资产，并在执行前再次确认。
- 支持把当前画布、原始媒体、预览、蒙版和全部约束快照导出为单个 `.canvaspack` 项目包；二进制媒体保持 Blob，不转成 Base64。
- 项目包导入前验证格式、长度、原文件和引用完整性，导入时创建独立项目副本并重新映射内部编号，不覆盖现有项目。
- 导入采用原子资产事务与失败回滚；导入项目会进入项目选择器并在刷新后恢复为上次打开的工作台。
- 定义可替换的对象存储接口；当前 IndexedDB 实现明确标记为“本地假远端”，用于零费用验证上传协议。
- 原文件按固定分片备份，支持暂停、继续、失败重试和异常退出后的会话恢复；已成功分片不会重复写入。
- 32 MB 内资产使用完整 SHA-256，超大资产使用固定分片 SHA-256 树指纹；不同项目的相同内容只保存一个假远端对象。
- 资产库显示逐项备份进度、失败原因、已备份/已复用状态和假远端实际占用，全流程不发起外网请求。
- 本地原文件丢失时，可从已完成的假远端分片备份恢复；恢复前重新校验分片摘要，恢复后保留原 `assetId`，画布与约束引用无需改写。
- API 具备默认关闭的对象存储签名网关合同；上传/下载凭证绑定租户、项目、资产、权限、有效期和单次使用状态。
- 服务端拒绝匿名签名、跨租户对象探测、只读成员上传、过期或篡改凭证，以及大小、MIME 或 SHA-256 不一致的上传。
- 当前签名网关仍为进程内假实现，不连接 S3、R2、OSS；完整边界说明见 `docs/object-storage-security-boundary.md`。
- 阶段 3 支持创建待确认批次；用户动作幂等键可恢复原批次，并拒绝同一幂等键下的参数漂移。
- 预计成本由服务端假定价器计算；人工确认必须匹配金额和币种，同时通过批次上限、项目预算和 `run:confirm` 权限检查。
- 确认后才冻结预算并按预期输出数量创建独立假任务；重复确认不会重复冻结或创建任务。
- 取消排队批次会取消未开始任务并释放预留；账本和审计采用追加记录，完整规则见 `docs/run-batch-cost-kernel.md`。
- 可控假调度器支持成功、部分失败、明确失败、慢任务超时和计费未知，并执行最大并发限制。
- 成功结果逐任务保留；超时不自动重试，人工重试创建带 `retryOf` 的新任务并重新检查成本。
- 假实际成本结算后立即释放估价差额；计费未知继续占用预留并禁止重试或取消。
- 任务内核支持可选的版本化状态存储；批次、任务、预算、账本、审计、预留和幂等索引可在服务重启后恢复。
- 文件状态存储使用同目录临时文件原子替换；损坏、预算配置漂移或金额不守恒的快照会被拒绝，不会静默清空。
- 文件单进程原型重启时，排队任务保持排队；中断前仍在运行的任务转为 `billing_unknown`，继续占用预留且不会自动重试。
- 本地工作台现使用 SQLite 事务适配器：每次操作在写锁下重载最新状态，任务、预算、账本和审计一次提交，数据库写入失败全部回滚。共享本机数据库的不同进程不会重复领取或覆盖余额。
- 项目上下文与预算登记共同提交；旧 JSON 只在首次迁移时读取，原文件不删除、不覆盖，数据库损坏时不会回退到旧账本。执行策略指纹防止其他服务改变定价、租约或并发上限绕过闸门。
- 数据库模式不会把其他进程仍在运行的任务误当成重启残留，只在执行租约到期后转入待核账并保留预留。SQLite 是本机零费用适配器，不替代规划中的生产 PostgreSQL，详情见 `docs/local-database-transactions.md`。
- 执行器先领取带编号和到期时间的任务租约，再凭当前租约启动；错误执行器或旧租约不能执行任务。
- 未启动租约到期后安全回到队列；已启动任务的租约到期则进入 `billing_unknown`，避免盲目重复调用供应商。
- 调度同时执行项目级并发、供应商适配器级并发和时间窗口启动限流，限流原因与建议重试时间写入返回值和审计。
- `billing_unknown` 由独立核账权限处理；核账人必须提交动作编号、预留快照、币种和外部证据引用。
- 确认已扣费时按核实金额结算并释放差额，确认未扣费时释放全部预留；两种结果都不会自动重试。
- 核账动作幂等且不可反向覆盖；实际扣费超过预留时保持冻结并升级处理，不会为了消除告警而伪造入账。
- 超预留账单可提交包含核实金额、证据、原因和拟审批批次上限的申请；申请期间保留原预留，不能绕过审批走普通核账。
- 超额审批要求独立 `run:approve-billing-overage` 权限，且申请人不能审批自己的申请；批准需项目剩余预算覆盖差额，不会提高项目总额度。拒绝或预算不足均不释放原预留、不自动重试。
- 超额申请与审批具备动作幂等、不可覆盖结论、跨重启恢复和快照一致性检查；完整规则见 `docs/billing-overage-approval.md`。
- 画布提供“任务与预算”面板：选择商品图和保存的约束、查看预估、人工确认、分段执行、单项重试、人工核账，以及结果回到画布。
- 本地开发工作台通过固定同源接口连接上述任务内核；项目默认模拟预算 ¥100，每个输出预估 ¥0.25、成功结算 ¥0.20，真实费用始终为零。
- 开发桥接核对输入、约束和蒙版底图归属；已登记快照不可覆盖。图片通过实际二进制、魔数、完整解码、尺寸与 SHA-256 校验后，原文件和服务端收据原子保存到本机 SQLite；创建、确认、领取、启动与重试都重新核对原文件，不再只信任浏览器登记信息。详见 `docs/verified-image-ingestion.md`。
- 原图和蒙版只在人工预估、确认、执行或重试时送到本机，不上传外网。蒙版绑定已验证底图的真实摘要和尺寸。原文件缺失/损坏会阻止执行；旧登记记录不会自动升级为已验证。
- 任务历史引用会保护原图资产；模拟结果只保存任务来源和锁定谱系，不伪造图片文件或资产编号。任务与预算响应不进入离线缓存。
- 新增仅供可信服务端调用的候选图片入库底座：实际字节经完整解码、尺寸和透明性检查后，原始二进制、权威收据、冻结请求/约束及输入转换谱系与资产目录在同一 SQLite 事务保存；同一任务重放复用资产，内容变化或记录损坏拒绝覆盖。
- 该底座需要必填的执行授权端口，目前只有测试夹具实现，尚未接到真实任务/租约或开放 HTTP 结果入口。好图、坏图和保存失败均不改变任务或费用；未知扣费仍保留预算预留，不能把资产入库当作任务成功或免费证明。
- 服务端可按租户/项目读取供应商目录和未确认图片准备单，公开数据不含地址及凭证引用；可信内部管理方法追加连续版本，不能覆盖旧版本。没有公共配置写入或凭证解析接口，默认不添加供应商/模型。
- 准备单只接收明确选择与资产编号，由服务端原图收据和约束补全快照；同动作恢复不重复估价，参数漂移冲突。准备单固定未确认/未授权，报价明确为本地假价格，不能直接用于任务执行。创建准备与资产入库共用输出边界，超尺寸及硬像素锁在估价前拒绝。

## 命令

```text
pnpm install
pnpm dev
pnpm check
```

本地开发要求 Node.js 24.19.0 或更新版本，使用内建 `node:sqlite`；无需安装云数据库，测试仍全部为零费用模拟。

图片核验使用锁定版本 sharp，安装时允许其本机依赖初始化。图片任务支持静态 PNG/JPEG/WebP/GIF/AVIF，单文件不超过 30 MiB、1600 万像素、单边 8192；每项目本机图片镜像上限 512 MiB。浏览器仍可管理视频/大媒体，但不能据此绕过图片任务上限。

新增候选输出入库仅接受合同允许的静态 PNG/JPEG/WebP，单文件不超过 20 MiB，沿用上述像素、边长及共享项目容量上限；原图/输出完整核验在同一进程最多并发 2 个。4096×4096 已超过 1600 万像素，后续执行衔接必须在报价/确认/发送前拒绝，不能先付费再静默缩图。未验收锁区保护，硬像素约束仍拒绝；这不是生产文件隔离沙箱。

打开本地工作台后，先“导入资产”，再“＋ 约束”并保存快照，最后打开“任务与预算”。当前默认执行器仅模拟图片精修，视频节点仍可管理但不能生成。

开发桥接只在 Vite 开发服务器启用，要求回环主机、同源和 `x-canvas-local` 请求标记；随机内部身份令牌只存在服务端。数据库为被 Git 忽略的 `work/local-studio-state/studio.sqlite`，可用 `CANVAS_STUDIO_STATE_DIR` 指定单独目录。共享只能在同一台电脑的本地磁盘上进行，不能放到网络盘；原 `runs.json` / `catalog.json` 迁移后只是历史备份，不再更新。测试使用独立临时状态目录，不污染日常工作台。纯静态生产构建没有此服务；任务面板会明确报错而不会假装执行。

核账填写的费用超过原预留时，面板改为“提交超额审批申请”，补充原因和拟审批上限后提交；在“超额审批记录”中可模拟批准或拒绝。开发桥接只为明确的审批路由提供 `local-reviewer` 身份，普通路由仍为 `local-designer`，页面明确提示这不是真实多人鉴权。正式 API 不提供此身份代入，必须接入真实成员与权限服务。

## 红线

- `apps/web` 不保存或读取供应商密钥。
- 浏览器不持有云存储密钥，也不能自行决定租户对象路径。
- 画布文档禁止媒体 Base64，只允许 `assetId`。
- API 与 MCP 共用任务、预算、审计和资产回流合同，但执行器彼此隔离。
- 生成谱系不可编辑；画布工作流边不能充当审计记录。
- 真实付费请求必须经过服务端人工确认与预算检查。
- 未完成假执行器的超时、部分失败和结算回归前，不开放真实供应商执行器。
